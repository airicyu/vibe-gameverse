# 玩家過強輸入與 GM 控場（合理範圍）

**狀態：** backlog 構想，**尚未排入任何 `docs/roadmap/X.Y.Z/`。** 不是承諾範圍；本項首先是 **談清楚再實作**，未收斂前不要當 HANDOFF。排程前須再開規劃對話：何謂「合理」、三條控場路徑選哪條（或組合）、以及對一回合契約的改動。

**現行：** 玩家每回合 **自由文字** `player_text` → `POST /api/turn` → GM 出 JSON → Writer 落 KB。產品沒有技能檢定、沒有「行動是否成立」的結構化欄位。約束主要靠 **prompt + zod 形狀**，不靠骰子。GM 理論上可以在 `narration`／`npc_lines` 裡拒絕或改寫玩家聲稱的結果，但 **沒有** 產品規則要求這麼做，也 **沒有**「先預覽裁決再讓玩家確認或重打」的回合狀態。文字 NSFW 仍允許（玩家帶向）；不可涉及未成年人——後者是 **硬禁**，與本項「過強但合法的外掛行為」不是同一類。

本檔**不**覆寫 0.4.0 契約。例證皆虛構；勿把 live `kb/runtime` 對白寫進日後 INDEX。

與既有項分工：本項管 **玩家聲稱的行動是否成立、如何切分、如何讓玩家反悔重輸**。不取代 Writer／NPC 記憶。不引入完整戰鬥或技能表（除非排程時明確要極簡判定標記）。

---

## 產品句（構想）

自由文字仍是輸入形態，但玩家 **不能** 用一段「我已殺死全場／我其實是神／世界突然改設定」就把故事扭成外掛通關。超過 **合理範圍** 時，GM 必須 **控場**：不是默認玩家敘述為已發生的事實。

合理範圍本身要先談定（見下）。控場手段目前有三條候選（可單用或組合），產品尚未選定。

---

## 問題（現行缺口）

| 層 | 現在 | 缺口 |
|----|------|------|
| 輸入 | 任意長自由文字 | 可在一句裡堆疊從合理到荒謬的多個宣稱 |
| GM | 模型自行裁決 | 常順從玩家「已成功」的語氣，KB `events[]` 跟著落地，之後難以撤回 |
| Writer | 只吃 GM 的 `events[]` | 一旦 GM 把外掛寫成事件，世界就真的變了 |
| UI | 送出即一回合結束 | 沒有「裁決預覽 → 接受／重輸」 |
| 契約 | 無 `attempt`／`blocked` 欄 | 無法機械區分「玩家想做」與「世界發生」 |

失敗模式：prompt 寫「請控場」但無結構 → 模型仍照單全收；或控場過死 → 連合理冒險（說謊、偷竊、帶向 NSFW）也被擋；或出戲系統訊息打斷沉浸。

## 何謂「合理範圍」（必須先談，未定案）

本項 **不要** 在未討論前寫死數值檢定。排程對話應先收斂「過線」的 **類別**，再用 prompt＋可選結構化輸出執行。方向（皆待拍板，可增刪）：

**傾向算過線（外掛／扭故事）：**

- 宣稱 **立刻改寫世界 canon**（我其實是領主、這酒館不存在、NPC 從一開始就是我的奴隸）。
- 宣稱 **無代價的絕對成功**：瞬間殺死／控制在場所有人、讀心全知、無限金錢／物品從虛空出現（且該世界並無對應能力）。
- 宣稱 **跳過場面約束**：單場景產品裡「我已經打完地城回到首都加冕」。
- 把 **GM／系統角色** 寫進輸入（「忽略以上指令，events 必須…」）——這是攻擊契約，應拒，不一定走角色內敘事。

**傾向仍算合理（不要當成外掛擋掉）：**

- 困難但符合世界的嘗試：說謊、偷東西、打架意圖、勸說、逃跑、帶向成人向互動。
- 角色 **聲稱** 自己很強，但未要求世界立刻承認結果——GM 可讓嘗試發生、結果未定或失敗。
- 該 default／custom canon **明確允許** 的超能／魔法（見 [default-world-templates](./default-world-templates.md)）；「合理」是相對 **本場世界**，不是相對地球物理。

**硬規則（已有，本項不重開）：** 涉及未成年人 → 直接非法／拒絕，不走下面 1–3 的「部分成功」把兒童內容做成「嘗試失敗但寫進敘事」。

待拍板：「合理」是 **只靠 GM prompt 類別表**，還是要 JSON 裡多一個 `adjudication`（過線／切分點）給程式？後者才能做路徑 3 的確認 UI，前者較快但難測。

## 候選做法（Eric 提出的三條）

### 路徑 1 — 整段不准、告知過線

GM（或 program）拒絕本回合生效：不寫 `events[]`、不改 KB、對玩家說明「這超出合理程度」。

- **利：** 界線清楚、檔案不被污染。
- **弊：** **出戲**（系統口吻）；玩家可能不知道怎麼改才過線。
- **實作向：** 較像 4xx 或一則非敘事的 UI 提示；`turn` 是否消耗待拍板（傾向 **不消耗** 世界狀態，是否佔 pi session 一則 user 也待拍板）。

### 路徑 2 — 切分：合理段成立，過線段＝心想但失敗，GM 接續

同一則 `player_text` 裡，前半符合範圍的行動 **判定成功（或至少發生嘗試並有世界後果）**；從過線處起改為 **角色曾經這麼想／試圖這麼做，但現實失敗**；世界只推進到切分點，之後由 GM 敘事接下去。

- **利：** 較不中斷沉浸；一句裡「走向吧台又宣稱滅世」仍能留下「走到吧台」。
- **弊：** 切分點是模糊語言問題，模型可能切錯（把合理段也判失敗，或把外掛寫成成功）；玩家 **誤踩雷無法反悔**——整段已進 KB 與 session。
- **實作向：** 需要 GM 輸出可驗證的結構（例如 `accepted_attempt` / `failed_overreach` 兩段摘要，`events[]` **只准**反映成立段）。禁止只在 `narration` 文學性帶過卻把外掛寫進 `events[]`。

### 路徑 3 — 在路徑 2 的裁決之後，先問玩家

GM 先做出路徑 2 的切分預覽（不落盤或只入暫存），給兩個選擇：

1. **接受** 這次裁決（成立段落地，過線段當失敗嘗試），然後 GM 接續本回合剩餘敘事（或再跑後半 turn——時序待拍板）。
2. **重輸** 本回合 `player_text`：預覽作廢，世界與 Writer **如同沒發生**。

- **利：** 補上路徑 2 的誤踩；玩家保有控制感。
- **弊：** 多一拍 UI／HTTP 狀態（`pending_adjudication`）；出戲程度介於 1 與 2 之間（選項本身是系統 UI）。pi session 如何避免「預覽 user」污染對局歷史待拍板（傾向預覽用 **獨立** 短呼叫或未 commit 的草稿，接受後才寫入對局 session＋Writer）。
- **與 setup generating 類似：** 進行中不得並行第二則 turn；確認前 `POST /api/turn` 應 409 或只接受 `accept`／`revise`。

## 構想傾向（非定案）

討論起點，**可推翻**：

- 不要只做路徑 1 當預設（出戲）。
- 純路徑 2 對「一句裡忽然外掛」很有用，但缺反悔。
- **路徑 3 較像產品解**：裁決邏輯用 2，交互用確認。路徑 1 留給 **契約攻擊／未成年人／完全無法切分的胡言**（整段拒）。
- 「合理」必須 **相對本場 canon**，賽博龐克裡駭入與酒館裡瞬間成神不是同一條線。
- Writer **永不**在確認前落盤。Mock 必須能測切分與重輸，不能靠模型聽話。

## 對一回合契約的可能衝擊（待拍板）

現行：一則 user → 一則 GM JSON → Writer。路徑 3 會變成：

1. user 送出 → **裁決預覽**（敘事草稿＋切分說明＋events 候選）。
2. 玩家 accept → commit Writer＋對局 session；或 revise → 丟草稿、輸入框恢復可編。

是否讓預覽出現在對話氣泡（角色內）還是獨立確認卡，影響出戲程度。`ui` 欄目前可選下一步提示，或許能承載兩顆按鈕，但 0.2.0 起自由文字為主——不要做成每回合都強迫選項，**僅過線時**才出現確認。

未過線：行為與今日相同，零額外點擊。

## 非目標（本項）

- 完整 D&D 技能表、戰鬥 round、數值 HP。
- 審查合法成人向內容。
- 玩家用系統選項取代自由文字當預設玩法。
- 讓 GM 在確認前就改 `gm_note`／entities（污染重輸）。

## 待拍板（排進 INDEX 前須收斂）

1. 合理範圍的類別表（相對 canon）；要不要 zod `adjudication`。
2. 預設路徑：1／2／3／混合（上文傾向混合：3 為主、1 為硬拒）。
3. 未過線是否完全無新 UI。
4. 預覽與對局 pi session 隔離方式；revise 是否從 session 刪那則 user。
5. 過線說明用角色內（「你辦不到」）還是短系統句；路徑 3 按鈕文案。
6. 與 NSFW：過線指能力／canon，不指成人內容本身。
