# L2 NPC 心理深度（目標／好惡）

**狀態：** backlog 構想，**尚未排入任何 `docs/roadmap/X.Y.Z/`。** 不是承諾範圍；排程前須再開規劃對話收斂已定案。

**現行：** [0.4.0](../0.4.0/INDEX.md) 已 shipped。`kind: "npc"` 有 `memory_tier` 0／1／2。L0／L1 池節與 L2 `current.json` 的 **`body` 都是主觀經歷摘要**（知情、態度、承諾、謊言），不是結構化心理欄。人設仍在 entity `persona`（對局 system）；`private_notes` 靜態且 **不進** `npc_memories`。Writer **不**為 NPC 記憶另開模型。升到 2 才有 `npc-memory/l2/{id}/current.json`。

本檔**不**覆寫 0.4.0 契約。例證皆虛構；勿把 live runtime 正文寫進日後 INDEX。

與 [npc-memory-files](../0.4.0/INDEX.md)／0.4.0 分工：既有項管 **分層經歷記憶**；本項在 **僅 L2** 上加 **可演的心理結構**（性格、人生／中期／短期目標、喜好／厭惡）。與 [0.5.0](../0.5.0/INDEX.md) 分工：compact 仍封存經歷；心理欄是否在 compact 時 distill／覆寫待拍板。L0／L1 **不要**這套欄位。

---

## 產品句（構想）

重要角色（`memory_tier === 2`）除了記得「發生過什麼」，還在 **NPC memory 落盤**裡帶一份可給 GM 用的心理骨架：性格、人生目標、中期目標、短期目標、喜好與厭惡。路人與短池角色不寫這份，避免每個打招呼的人都有完整內在戲。

GM 寫該角台詞時，應能同時看到：該角 L2 `body`（近事）＋這份心理欄（為何而動）。不要只靠 `persona` 一段散文硬撐長期動機。

---

## 現行行為（錨點）與缺口

| 層 | 現在 | 缺口 |
|----|------|------|
| `persona` | 語氣／怎麼演，在 `entities.json`，進 **system** | 很少維護「這週想幹什麼」；與經歷檔分離 |
| `private_notes` | 靜態秘密，不進 `npc_memories` | 不是可更新的目標層 |
| L2 `current.json` | `{ npc_id, body, updated_turn }`，`body` ≤ 800 | 只有近事摘要，沒有目標／好惡結構 |
| 池 L0／L1 | 單節 `body` | **本項刻意不擴** |
| Writer | 機械把本回合知情追加進 body | 不會維護目標是否過期、達成、改寫 |
| 對局讀取 | present 的 L2 只餵 `body` | GM 看不到結構化動機（除非寫進 persona／body 混成一團） |

失敗模式：把心理欄寫進所有 npc → prompt 膨脹、路人戲過重；或把目標抄進 `persona` 導致 system 與 memory 雙源打架；或每回合 LLM 重寫性格導致角色人格漂移。

## 範圍：只限 L2

- **有這份結構：** `memory_tier === 2` 且存在 `l2/{id}/`（開場 seed L2，或遊玩中 1→2）。
- **沒有：** L0／L1 池節不加欄。升 2 **當時** 才建心理區塊（可極短／待填，見下）。
- 降級不存在（0.4.0：L2 永不降）。刪 L2 目錄只發生在 new-game／清盤。
- Custom 開場仍不灌 L2 → **開打時沒有**這份心理檔；該角升 2 之後才有。Default 瑪拉／灰開場即可有初值。

## 構想：欄位（名稱待拍板）

落在 **npc-memory 的 L2 側**，不要複製一份進 `entities.json`（避免與 `persona` 搶「人設真相」）。傾向擴 `current.json` 或同目錄另檔（擇一寫進排程 INDEX）：

1. **同檔** `current.json` 加物件 `psyche`（或平鋪欄）。讀寫一次、升 2 原子較單純。
2. **另檔** `l2/{id}/psyche.json`：經歷 `body` 截斷頻繁、心理較穩，分開可少誤覆寫。Writer 更新近事時較不易踩到目標欄。

欄位方向（皆短字串，硬上限待拍板；虛構例勿當 canon）：

| 欄 | 用意 | 穩定性 |
|----|------|--------|
| 性格 | 氣質／防衛方式／價值（可比 `persona` 更短、更內在） | 很少改 |
| 人生目標 | 長年想成為／守護／逃開的事 | 很少改 |
| 中期目標 | 本季／本場弧的方向 | 偶發改（達成、破滅、被玩家打斷） |
| 短期目標 | 今晚／這幾回合想做成的一件事 | 較常改 |
| 喜好 | 人／物／氣氛／話題 | 偶發增刪 |
| 厭惡 | 同上 | 偶發增刪 |

禁止：把整段 `npc_lines` 貼進任一欄；禁止把世界地圖或任務系統塞進來。仍單場景 POC。

`persona` 繼續管 **怎麼說話**。心理欄管 **要什麼、怕什麼**。Prompt 須寫：台詞優先心理欄的目標／好惡；語氣跟 `persona`；近事跟 `body`。三者衝突時的優先序待拍板（傾向：**短期目標與近事可蓋過過時中期**；性格不因一回合翻盤）。

## 誰寫、何時改（待拍板，須防人格漂移）

0.4.0 原則是 **不為記憶每回合開模型**。本項若每回合讓 GM JSON 帶心理欄，等於擴對局契約、易漂。構想傾向分層：

| 時機 | 誰 | 改什麼 |
|------|----|--------|
| Default seed／setup | 產品預寫 | 瑪拉／灰等開場 L2 的初值 |
| 升 2 | Writer 機械 | 建空或從 `persona`／池 body **截一句**當性格草稿（規則待拍板；寧可短） |
| 每回合 | 預設 **不**重寫性格／人生目標 | 至多機械標「短期目標是否仍與本回合 event 相容」——過強則不要做 |
| Compact 或偶發 distill | **可**另開一次模型（整場一次，不是每回合） | 依 archive／近事更新中期／短期／好惡；性格與人生目標需更強證據才改 |

禁止擴充對局 GM JSON 讓模型每回合覆寫全部心理欄——除非排程時明確推翻，並加 zod 長度與「性格不可空改」約束。

`private_notes` **不**自動灌進心理欄（雙源、且 notes 不進 `npc_memories` 的既有 BAN 仍在）。開場秘密可 **人工**寫進 seed 的厭惡／目標，不要 runtime 合併兩欄。

---

## 誰讀

組 `npc_memories` 時：L2 除 `body` 外附上心理欄（present 才餵，規則同 0.4.0）。L0／L1 仍只有 `body`。HTTP 對玩家 **仍不**出 `npc_memories`。UI 不做心理編輯器（非目標）。

`near_cap` 仍只看經歷 `body` 長度，不算心理欄字數——除非同檔導致 current 過肥，那時更應拆 `psyche.json`。

---

## 非目標（本項）

- L0／L1 心理檔；每個開口路人都有人生目標。
- 真・多 agent、每 NPC 獨立 pi session。
- 玩家可見的角色表／好感度儀表。
- 把心理欄當任務系統或多地點動機引擎。
- 廢除 `persona` 或 hop 把舊 `body` 自動拆成六欄（無標記舊存檔：缺欄＝空字串合法，等 compact／下次升 2 再填）。

---

## 待拍板

1. 同檔 vs `psyche.json`；JSON 鍵名；各欄 UTF-16 上限。
2. 升 2 時初值：全空合法，還是必填性格一句。
3. 更新節奏：僅 compact distill，或 Writer 對短期目標做極保守機械修補。
4. 與 `persona` 重複時以誰為準（寫進 GM 短規則）。
5. Default 瑪拉／灰預寫深度做到哪（仍不要改酒館故事核，除非另開模板項）。
